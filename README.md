# 라면 R&D 연구소

식품개발연구원이 되어 기본 베이스와 시판 스프를 응용하는 진로체험 웹앱입니다. 학생은 **사용한 재료의 무게(g)와 맛 느낌 한 줄**을 기록합니다.

## 수업에서 쓰는 방법

1. 교사는 첫 화면의 **교사 설정 화면** 버튼(또는 `/teacher`)으로 바로 입장합니다. 별도 비밀번호 입력은 없습니다.
2. **수업·반 설정 → 수업 추가**에서 학교·반·수업일을 적고 설정을 저장합니다. 반마다 다른 6자리 숫자 입장 코드가 자동으로 만들어집니다.
3. 재료 관리에서 실제 포장지의 알레르기를 확인하고 체크합니다. 시판 스프와 사리면도 별도로 확인합니다. 초기 알레르기는 모두 ‘확인 전’입니다.
4. **직업소개·공정시연**에서 직업 소개 7장과 기존 면 생산공정을 전자칠판으로 발표합니다.
5. 학생은 수업 코드로 들어와 기본 베이스 / 시판 스프 탭에 기록합니다. 국물 연습은 자유롭게 추가하고 라면 시식은 탭마다 한 번, 총 두 번입니다.
6. **학생 레시피 보기**에서 한 학생의 두 방법을 나란히 띄웁니다. 이전·다음 버튼, 방향키, 좌우 넘기기, ESC/닫기를 지원합니다. 5초마다 갱신되며 수동 새로고침도 있습니다.
7. 원하면 최종 레시피를 선택하고 스티커를 인쇄하거나 우리 반에 공유합니다. 점수·평가·순위·입력 잠금은 없습니다.

## 기록과 개인정보

- 새 학생에게 이름이나 개인 알레르기를 묻지 않습니다. 서버에는 반별 연구원 번호가 붙습니다.
- 인쇄 이름은 화면 메모리에서만 사용하며 서버/로컬 저장소로 보내지 않습니다.
- 사용한 재료의 알레르기는 실제 포장 정보를 기준으로 합산합니다. 교사의 확인 완료가 없으면 경고를 표시합니다. 이름이나 분말 종류로 알레르기를 추정하지 않습니다.
- 학생 기록에는 별도 소유 키가 필요합니다. 친구 공유 응답에는 원래 학생 ID·소유 키·이름·연습 기록이 포함되지 않습니다.
- 입력은 즉시 이 기기에 저장한 뒤 순서대로 서버에 자동 저장합니다. 연결 실패 시 저장 상태를 표시하고 재시도합니다. 다른 창의 저장과 충돌하면 덮어쓰지 않고 현재 기록 내려받기를 안내합니다.
- 다른 기기로 옮길 때 자동으로 동일 학생으로 합쳐지지 않습니다. ‘기록 내려받기’는 JSON 보관용이며 자동 복원/이관 도구는 아닙니다.
- 기존 `experiments`, 이름, 팀, 라벨 데이터는 DB에서 변경/삭제하지 않습니다. **반 정보 없는 이전 기록**에서 기존 라벨 출력과 기록 열람이 가능합니다. 새 수업과 자동 혼합하지 않습니다.
- 재료 삭제/비활성화는 이후 선택 목록에 적용되며 새 기록의 재료 스냅샷은 보존됩니다.

## 스티커

원형 지름 9cm / 사각 9 × 9cm, 앞·뒷면 별도, A4에 여러 장 배치합니다. 실제 크기 100%, 머리글/바닥글 끄기로 인쇄합니다. 긴 원재료·알레르기 표시는 추가 뒷면에 나누어 출력합니다. 학생별 출력과 반 전체 출력 모두 지원합니다. 점수는 넣지 않습니다.

## 발표 자료

교사 화면의 ‘발표 출처·이미지 생성 프롬프트’에 슬라이드별 프롬프트를 제공합니다. 같은 내용은 [발표 자료 안내](docs/teacher-slides.md)와 `lib/career-slides.ts`에 있습니다. 현 슬라이드는 기존 시연 이미지로 구성하며 새 이미지를 생성했다고 표시하지 않습니다.

## 개발 및 배포

Node.js 22.13 이상. `npm ci` 후 Next.js 프런트는 `npm run dev`, 로컬 D1/R2 포함 검증은 `RAMEN_API_ORIGIN=local npx vite`를 사용합니다.

Vercel에서는 `proxy.ts`가 기존 Sites API에 서버 인증을 붙여 연결합니다. Vercel 프로젝트의 Production 환경에 기존 Sites API 토큰을 `RAMEN_API_TOKEN`이라는 민감 환경 변수로 저장해야 합니다. `NEXT_PUBLIC_` 접두사를 붙이거나 소스에 토큰을 넣지 않습니다. 저장 서버의 공개 범위는 변경하지 않습니다. `RAMEN_API_ORIGIN`을 설정한다면 기존 Sites 주소만 사용할 수 있습니다. 로컬 데이터 검증은 Vite의 D1을 사용합니다.

서버 연결·로그인 회귀 검증: `node --experimental-transform-types --test tests/backend-proxy.test.mjs`.

- GitHub/Vercel 프런트의 기본 API 대상: 기존 Sites 저장 서버. `/api/teacher/*`도 같은 서버로 전달합니다.
- Sites 저장 서버는 로컬 API로 빌드해야 합니다. 프런트와 서버의 새 버전을 함께 반영해야 반별 기록 API가 동작합니다.
- 기존 D1 테이블의 JSON 필드를 확장했습니다. 기존 학생 레코드와 설정을 일괄 덮어쓰는 마이그레이션은 없습니다.
- 교사 세션은 예측 가능한 고정 쿠키 대신 서버 발급 임시 세션을 사용합니다. 업데이트 후 다시 로그인해야 합니다.
- 저장 검증: `npx tsc --noEmit`, `npx eslint .`.
- 다중 브라우저 통합 검증: 로컬 Vite 서버를 켜고 `PLAYWRIGHT_MODULE_PATH=/path/to/playwright CHROME_PATH=/path/to/chrome node tests/notebook-e2e.cjs`. 로컬 테스트 반을 생성하며 운영 URL에서는 실행을 거부합니다.
