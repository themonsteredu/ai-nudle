# 식품개발연구원 수업 — 새 Work/Codex 작업 명세

관련 요구사항: GitHub 이슈 #11. 사용자는 명세 등록만이 아니라 **새 작업 세션에서 실제 구현을 시작**하도록 요청했다.
이 파일은 새 클라우드 작업을 호출하기 위한 명세이며, 구현 완료를 뜻하지 않는다.

## 반드시 지킬 수업 구조

A. 기본 베이스 연구: 기본 베이스 + 추가 분말 → 미니컵 국물 연습 → 마음에 드는 조합 선택 → 라면사리 ¼개를 넣어 조리·시식 1회.
B. 시판 스프 응용: 시판 라면스프 + 추가 분말 → 미니컵 국물 연습 → 마음에 드는 조합 선택 → 라면사리 ¼개를 넣어 조리·시식 1회.

실제 면 시식은 총 2회다. 국물 연습은 필요할 때 기록을 추가하고 4회로 강제하지 않는다.
건더기는 국물 연습에서 제외하고 실제 면 조리·포장에만 사용한다.
실물 배합·시식을 웹의 가상 체험으로 대체하지 않는다.

## 학생 화면: 레시피와 맛 느낌만

- ‘기본 베이스’와 ‘시판 스프’ 두 탭. 각 탭 안에서 국물 연습 기록과 라면 시식 기록을 구분한다.
- 학생 입력은 사용한 베이스·재료·실제 계량량(g), 맛 느낌 한 줄이다. 교사가 준비한 재료만 표시한다.
- 이름 등 기존 식별 정보는 한 번만 받는다. 물의 양과 공통 조건은 교사 설정값을 표시하고 반복 입력시키지 않는다.
- g 직접 입력과 저울에 맞춘 증감 버튼을 제공한다.
- 연습 기록 추가, 레시피 복사·수정, 선택한 레시피로 라면 시식 기록 기능을 제공한다. 복사 후 수정해도 원본은 보존한다.
- 국물 시료와 실제 라면에 사용한 양은 혼동 없이 별도로 기록한다.
- 자동 저장, 새로고침 복원, 일시적 연결 실패 시 입력 보존 및 저장 상태 표시를 구현한다.
- 점수, 퀴즈, 단계 잠금, 고정 실험 횟수, 필수 비교·최종 선정, 긴 보고서, 추가 진로소감·개선계획 필수 입력을 만들지 않는다.
- 직업 소개와 제조공정 체험은 학생 필수 진행 단계에서 제외한다. 기존 제조공정·라벨·출력 기능과 데이터는 보존하되 기본 기록 흐름과 분리한다.

## 교사 화면: 직업소개 발표 보강

현재 확인한 코드에는 짧은 직업 설명과 면 생산공정 시연이 있고, 별도 PPT 파일은 없다. 작업 시작 시 최신 코드와 화면을 다시 확인한다.

- `components/teacher/CareerProcessPanel.tsx`를 확인하고 직업 소개부터 전체화면으로 넘길 수 있는 교사용 발표 화면을 보강한다.
- 식품개발연구원의 업무, 신제품 개발 과정, 배합·시식·기록·수정의 이유, 필요한 역량·관련 직무, 오늘의 A/B 수업 안내를 다룬다.
- 직업 사실은 신뢰할 수 있는 출처를 확인한다. 제조공정 설명만으로 직업 소개를 대체하지 않는다.
- 기존 9개 공정 자료·시연을 재사용한다. 실제 PPT 파일 제작을 새 필수 범위로 확대하지 않는다.
- 학생에게 슬라이드 완료나 퀴즈 풀이를 요구하지 않는다.

## 설정과 기존 데이터

- 기본 베이스와 시판 스프 제품·기준량을 별도로 설정한다.
- 국물 연습용 물, 실제 면 조리용 물, 선택적 포장 기준을 분리한다.
- 과거 대화의 예시 g 수치는 검증된 레시피가 아니므로 하드코딩하지 않는다.
- 계량 단위·시작량·조리 기준은 교사가 실제 제품과 저울에 맞춰 설정한다.
- 면 ¼개라는 이유만으로 일괄 4배 환산하지 않는다. 산술 환산을 검증된 완성 조리법으로 표시하지 않는다.
- 모든 분말을 온수에 타기만 해도 먹을 수 있다고 안내하지 않는다. 실제 제품 조리법·알레르기 확인을 유지한다.
- 준비물·원가·수업지도안·인쇄·README의 고정 4회 전제를 수정한다. 면 시식 2회와 포장용을 별도로 계산한다.
- 기존 학생 기록과 교사 설정을 삭제하거나 덮어쓰지 않는다. 데이터 구조 변경 전 호환·이관 방법과 테스트를 마련한다.
